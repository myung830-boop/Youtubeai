### #4 사용방법 5단계 (2:20–3:50)
화면 녹화 + 단계 번호 카드. 각 단계 15~20초.

| 단계 | 화면 | 대사 핵심 |
|---|---|---|
| ① 가입 | lovable.dev 접속, 구글 로그인 | "구글 계정으로 1분이면 가입" |
| ② 첫 요청 쓰기 | 실제 첫 프롬프트 화면 | "제가 처음 쓴 문장은 이거예요" → `[실제 첫 프롬프트]` |
| ③ 미리보기 확인 | 오른쪽 미리보기에 앱이 생기는 장면 (빨리감기) | "기다리면 오른쪽에 앱이 생겨요" |
| ④ 고치기 | "버튼 더 크게 해줘" 같은 수정 요청 | "마음에 안 들면 그냥 말로 고쳐달라고 하면 됩니다" |
| ⑤ 게시 | Publish 버튼 → 주소 생성 | "게시 누르면 주소가 생기고, 손님한테 보낼 수 있어요" |

**팁 카드 (화면 고정):** 처음 요청에 넣으면 좋은 3가지
- 우리 가게가 **뭘 하는 곳**인지 (신발 세탁, 접수→세탁→완료 흐름)
- **누가** 쓰는지 (사장님용 / 손님용)
- **꼭 필요한 기능** 3개만 먼저

| 내 실제 사용량 (StatBar) | "저는 이 시스템 만드는 데 **[ ]크레딧, [ ]개월, 약 [ ]원** 썼습니다." | 놀람 |
| 문자 비용 별도 카드 | "단, 문자 발송은 [문자 서비스 이름] 비용이 따로 들어요. 건당 [ ]원." | 걱정 |

### #6 우리 가게 시스템 공개 (5:00–7:50) — 핵심 파트
각 기능을 **[전: 고민] → [요청한 말] → [후: 화면]** 3박자로 40초씩.

| 기능 | 전 (BeforeAfter 왼쪽) | 러버블에 한 요청 (ChatMockup) | 후 (실제 화면 녹화) |
|---|---|---|---|
| ① 접수 | 종이 장부 | `[실제 프롬프트 예: 손님 이름, 전화번호, 신발 종류, 서비스, 가격을 입력하는 접수 화면 만들어줘]` | 접수 화면, 접수번호 자동 생성 |
| ② 사진 관리 | 사진첩에 섞인 사진 | `[실제 프롬프트]` | 접수건마다 입고·완료 사진이 붙는 화면 |
| ③ 문자 발송 | 한 명씩 직접 문자 | `[실제 프롬프트]` | '세탁 완료' 버튼 → 손님 휴대폰에 문자 도착 |
| ④ 손님용 주문 앱 | 전화 문의 | `[실제 프롬프트]` | 손님이 휴대폰으로 주문·진행상황 확인 |

마지막에 **전체 흐름 한 장** (ProblemToSolution):
`손님 접수 → 입고 사진 → 세탁 → 완료 사진 → 자동 문자 → 손님 앱에서 확인`

## 4. 촬영 전 준비물 체크리스트
**화면 녹화 (PC 화면 녹화 + 휴대폰 화면 녹화)**
- [ ] lovable.dev 첫 화면, 가입 과정
- [ ] 처음 프롬프트를 입력하고 앱이 생성되는 과정 (이미 만들었다면 새 프로젝트로 간단히 재연)
- [ ] 수정 요청 1~2번 하는 장면
- [ ] 크레딧 잔량 / 요금 페이지
- [ ] 접수 화면에서 실제로 1건 접수
- [ ] 사진 올리기
- [ ] '완료' 누르고 휴대폰에 문자 도착하는 장면 (휴대폰 화면 녹화)
- [ ] 손님 앱에서 주문·진행상황 보는 장면 (휴대폰)

**자료**
- [ ] 각 기능별로 러버블에 실제로 쓴 요청 문장 (러버블 채팅 기록에서 복사)
- [ ] 사용한 크레딧, 기간, 비용, 문자 서비스 이름과 건당 비용
- [ ] 전후 변화 숫자 (전화 문의 수, 접수 시간 등)

**⚠️ 개인정보**
- 손님 이름·전화번호·주소는 **테스트용 가짜 데이터**로 촬영하거나 모자이크
- 손님 신발 사진도 동의받은 것만 사용
