# 사장님 AI 실험실 — 채널 & 모션그래픽 시스템 기획서

> 이 문서의 원칙: **"영상 한 편을 만드는 게 아니라, 영상을 찍어내는 틀을 한 번 만든다."**
> 디자인은 코드 컴포넌트로 한 번 만들고, 매 영상은 **대본 + 장면 데이터(JSON)** 만 바꿔 끼운다.

## 1. 채널 정체성 (먼저 고정할 것)

| 폰트 | Pretendard (Bold / Medium / Regular) |

2. **업종별 레시피** — "카페 사장님이 바로 쓰는 프롬프트 3개"
3. **솔직 결산** — "AI 한 달 써보니 아낀 시간/돈, 실패한 것"

## 2. 무엇부터 만들까 — 우선순위

### ① 캐릭터 에셋 (가장 먼저, 가장 중요)
AI 이미지로 매번 새로 뽑으면 얼굴이 계속 바뀝니다. **한 번 포즈 시트를 만들고 그걸 영원히 재사용**합니다.

필요한 포즈 (투명 배경 PNG, 정면 상반신, 같은 크기/같은 기준선):

| 파일명 | 표정/포즈 | 쓰는 장면 |
|---|---|---|
| `boss-default.png` | 기본 미소 | 인트로, 일반 설명 |
| `boss-think.png` | 턱 괴고 고민 | 문제 제기 ("손님 응대가 너무 많아…") |
| `boss-point.png` | 손가락으로 가리킴 | 리스트/화면 설명 |
| `boss-happy.png` | 주먹 쥐고 신남 | 결과/변화 |
| `boss-surprise.png` | 놀람 | 반전, 의외의 결과 |
| `boss-worry.png` | 걱정/땀 | 실패담, 주의사항 |
| `boss-wave.png` | 손 흔들기 | 엔딩/구독 요청 |
| (선택) `boss-*-blink.png` | 눈 감은 버전 | 깜빡임 애니메이션용 |

> **여기까지만 만드세요.** 립싱크, 뼈대(리깅) 애니메이션, 3D는 처음엔 필요 없습니다.
> 포즈 교체 + 살짝 튀어오르기(spring) + 흔들림 + 깜빡임만으로 충분히 "살아있는" 느낌이 납니다.

### ② 스타일 토큰 (`src/styles/theme.ts`)
색, 폰트, 여백, 모서리 둥글기, 애니메이션 속도를 **한 파일**에 모읍니다. 모든 컴포넌트는 이 값만 참조합니다.

### ③ 재사용 컴포넌트 8개 (이것만 있으면 영상 90%가 만들어짐)

| # | 컴포넌트 | 역할 | 이미지 레퍼런스 |
|---|---|---|---|
| 1 | `TitleCard` | 큰 질문형 제목 + 캐릭터 | A안 "사장님도 AI를 직원처럼…" |
| 2 | `CharacterTalk` | 캐릭터 + 말풍선/생각풍선 | B안 생각풍선 |
| 3 | `Checklist` | 체크 항목이 하나씩 등장 | B안 "고객 응대 / 예약 관리 / 매출 분석" |
| 4 | `ProblemToSolution` | 고민 → AI → 변화 3단 흐름 | B안 화살표 |
| 5 | `ChatMockup` | AI 채팅 화면 (질문/답변 타이핑) | 실제 사용 시연 |
| 6 | `BeforeAfter` | 좌우 비교 (시간·비용) | 결과 강조 |
| 7 | `StatBar` | 숫자 카운트업 / 막대그래프 | A·C안 막대그래프 |
| 8 | `EndCard` | 요약 + 구독 유도 | 엔딩 |

공통 레이어: `Subtitle`(하단 자막), `Background`(가게 배경/단색), `BGM`.

### ④ 고정 오프닝/엔딩
- 인트로 2~3초 (로고 + 캐릭터 손 흔들기) — 한 번 만들고 끝
- 엔딩 5초 — 한 번 만들고 끝

## 3. 어디까지 만들까 — 범위 정하기

| 단계 | 범위 | 기준 |
|---|---|---|
| **v0 (1주차)** | 포즈 7장 + theme + 컴포넌트 3개(TitleCard, CharacterTalk, Checklist) + 쇼츠 1편 | "렌더해서 MP4가 나온다" |
| **v1 (2~3주차)** | 컴포넌트 8개 완성, 장면 JSON으로 영상 생성, 자막 자동 | "대본만 바꾸면 새 영상이 나온다" |
| **v2 (2달차~)** | 롱폼 레이아웃, 썸네일 템플릿 코드화, TTS 자동 연결 | "1편 1시간 이내" |

**하지 말 것 (처음엔):** 립싱크, 캐릭터 관절 애니메이션, 3D, 복잡한 파티클, 매 영상 새 배경 일러스트.
→ 반응을 본 뒤 조회수가 잘 나오는 포맷에만 투자하세요.

## 4. 가볍게 운영하는 구조 — "대본 → JSON → 렌더"

```
대본(텍스트) ──AI──▶ scenes.json ──Remotion──▶ MP4
                         ▲
               컴포넌트 이름 + 텍스트만 들어감
```

### 장면 데이터 예시 (`script/ep001.json`)
```json
{
  "id": "ep001",
  "title": "리뷰 답글, AI한테 맡겨봤습니다",
  "format": "shorts",
  "scenes": [
    { "type": "TitleCard", "pose": "think", "text": "리뷰 답글,\nAI한테 맡겨도 될까?", "sec": 3 },
    { "type": "CharacterTalk", "pose": "worry", "bubble": "하루 30개씩 답글 달다 보면…", "sec": 3 },
    { "type": "ChatMockup", "question": "별점 2개 리뷰에 정중한 답글 써줘", "answer": "소중한 의견 감사합니다…", "sec": 6 },
    { "type": "BeforeAfter", "before": "답글 1개 5분", "after": "답글 1개 30초", "sec": 4 },
    { "type": "Checklist", "items": ["톤 지정하기", "가게 이름 넣기", "마지막엔 직접 검토"], "sec": 5 },
    { "type": "EndCard", "pose": "wave", "text": "다음 실험도 같이 해요!", "sec": 3 }
  ]
}
```

매 영상에서 사람이 하는 일은 **이 JSON을 확인/수정하는 것뿐**입니다. 디자인은 손대지 않습니다.

### 주간 루틴 (쇼츠 2편 + 롱폼 격주 1편 기준)

| 요일 | 할 일 | 시간 |
|---|---|---|
| 월 | 주제 2개 선정 + 실제로 AI 써보기(실험) | 1h |
| 화 | 대본 작성 → AI로 scenes.json 변환 | 1h |
| 수 | 미리보기(Remotion Studio)에서 텍스트/타이밍만 수정 | 30m |
| 목 | 음성(TTS 또는 직접 녹음) + 렌더 + 썸네일 | 1h |
| 금 | 업로드 + 댓글 확인 → 다음 주제 메모 | 30m |

### 포맷 전략
- **쇼츠(1080×1920, 30~50초) 먼저.** 제작 부담이 적고, 어떤 주제가 반응 오는지 빠르게 테스트됩니다.
- 반응 좋은 쇼츠 주제 → **롱폼(1920×1080, 5~8분)** 으로 확장. 같은 scenes 구조, 레이아웃만 다른 Composition.

## 6. AI 코딩 도구에 줄 고정 프롬프트

### (1) 최초 세팅용 — 한 번만
```
'사장님 AI 실험실' 유튜브 채널용 Remotion 프로젝트를 만들어줘.
- docs/CHANNEL_PLAN.md의 폴더 구조, 컬러, 폰트를 그대로 따를 것
- src/styles/theme.ts에 모든 디자인 값을 모으고, 컴포넌트는 theme만 참조
- Boss 캐릭터 컴포넌트: pose prop으로 public/character/boss-{pose}.png 교체,
  등장 시 spring 바운스, 3초마다 깜빡임(blink 이미지가 있으면)
- SceneRenderer: script/*.json의 scenes 배열을 받아 type별 컴포넌트로 순서대로 렌더
- Composition 2개: Shorts(1080x1920), Longform(1920x1080), 30fps
- 우선 TitleCard, CharacterTalk, Checklist 3개만 구현
```

### (2) 매 영상용 — 반복
```
아래 대본을 script/epXXX.json 형식으로 변환해줘.
- 사용 가능한 type: TitleCard, CharacterTalk, Checklist, ProblemToSolution,
  ChatMockup, BeforeAfter, StatBar, EndCard
- pose: default, think, point, happy, surprise, worry, wave
- 흐름은 반드시 [고민 → AI 활용 → 변화 → 정리] 순서
- 한 장면 텍스트는 2줄, 줄당 14자 이내
- 새 컴포넌트나 새 색상을 만들지 말 것

대본:
(여기에 붙여넣기)
```

> 핵심: **"새 컴포넌트/새 색 만들지 말 것"** 을 매번 넣어야 스타일이 흔들리지 않습니다.

## 8. 체크 포인트 / 주의사항

- **Remotion 라이선스:** 개인·소규모 팀은 무료지만 회사 규모가 커지면 유료 라이선스가 필요합니다. 시작 전에 공식 라이선스 조건을 한 번 확인하세요.
- **캐릭터 이미지 권리:** AI로 만든 캐릭터는 사용한 도구의 상업적 이용 약관을 확인하세요.
- **BGM/폰트:** 상업 이용 가능한 것만 (Pretendard는 OFL로 무료 사용 가능).
- **음성:** 처음엔 직접 녹음도 좋습니다. "진짜 사장님" 느낌이 채널 신뢰도에 유리합니다. 부담되면 TTS로 시작.
- **AI 결과는 실제로 써본 화면을 보여주기:** 채널의 핵심 가치는 '실험'입니다. 모션그래픽은 포장, 내용은 실제 사용 경험.
